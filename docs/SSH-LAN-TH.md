# SSH LAN — คู่มือสั้น

## เริ่มใช้

1. สร้างไฟล์โปรแกรมครั้งแรก: `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\build-launcher.ps1`
2. ดับเบิลคลิก **`SSH LAN.exe`** (หรือรัน `scripts\app.ps1` ตรงๆ)
3. เครื่องที่จะ **รับ SSH**: ติดตั้ง *OpenSSH Server* ใน Windows ก่อน แล้วกด **เปิดใหม่แบบผู้ดูแล** → เลือกวงที่อนุญาต → **เปิดรับ SSH**
4. เครื่องที่จะ **เชื่อมต่อ**: กดปุ่มหลัก (ตั้งเครื่องนี้ให้เชื่อมต่อ) ครั้งเดียว

โปรแกรมเลือกบทบาทให้เอง: เครื่องที่มีบริการ OpenSSH Server คือเครื่องรับ ที่เหลือคือเครื่องเชื่อมต่อ

## ปุ่มบนเครื่องรับ SSH

- **เปิดรับ SSH** เปิดบริการ, อนุญาตพอร์ต 22 เฉพาะวงที่เลือก, ปิดรหัสผ่าน ใช้กุญแจเท่านั้น
- **ทดสอบการเชื่อมต่อ** ตรวจบริการ พอร์ต และไฟร์วอลล์
- **เพิ่มกุญแจเครื่องอื่น** คัดลอก public key ของเครื่องนั้นไว้ใน Clipboard แล้วกดปุ่มนี้
- **อัปเดตสถานะ** รีเฟรช IP และสถานะบริการ
- **สแกน / ควบคุมเครื่องใน LAN** เปิดหน้าต่างสแกน: ดูทุกเครื่องในวง สั่ง SSH, Remote Desktop, ปลุกเครื่อง, รันคำสั่ง และเชิญเครื่องใหม่ (ดูหัวข้อข้างล่าง)
- **ปิดการรับ SSH** หยุดบริการและลบกฎไฟร์วอลล์

## ตั้งเลข IP คงที่

ช่องเลข IP จะใส่เลขปัจจุบันให้ก่อน พิมพ์เลขเต็ม (`192.0.2.50`) หรือเฉพาะตัวท้าย (`50`) แล้วกด **ตั้งเลข IP คงที่**

- โปรแกรมตรวจว่าเลขอยู่ในวงเดียวกัน ไม่ใช่เลขของเราเตอร์ และไม่มีเครื่องอื่นใช้อยู่ ก่อนเปลี่ยนจริง
- ถ้าเปลี่ยนไม่สำเร็จ จะสลับกลับเป็น DHCP ให้เอง เครื่องไม่หลุดจากเครือข่าย
- กด **คืนเป็น IP อัตโนมัติ** เมื่ออยากกลับไปใช้ DHCP
- การตั้งแบบนี้ล็อกเลขที่ตัวเครื่อง เราเตอร์ยังแจกเลขเดียวกันให้เครื่องอื่นได้ ควรเลือกเลขนอกช่วงที่เราเตอร์แจก หรือจองเลขไว้ที่เราเตอร์ด้วย

## จับคู่เครื่อง (ให้เครื่องคุยกันเองได้)

พิมพ์ `ผู้ใช้@IP` ของเครื่องอื่นในช่อง "จับคู่กับเครื่องอื่น" แล้วกด **จับคู่เครื่อง** (เว้นช่องว่างแล้วกดเพื่อสแกนหาเครื่องที่เปิดพอร์ต 22) จะมีหน้าต่างให้พิมพ์รหัสผ่านของเครื่องนั้น (โปรแกรมไม่เห็นรหัสผ่าน)

- เครื่องปลายทางเป็น **Windows, Linux หรือ macOS** ก็ได้ โปรแกรมดูจากแบนเนอร์ของ sshd แล้วเลือกคำสั่งให้เอง
- เครื่องนี้สร้างกุญแจของตัวเอง ส่งเฉพาะ **public key** ไปวางที่ปลายทาง ทดสอบว่าเข้าด้วยกุญแจได้จริง แล้วเขียนชื่อเรียกใน `~/.ssh/config` (ใช้ `ssh ชื่อ` ได้เลย)
- ติ๊ก **ให้เครื่องนั้นเข้ามาหาเครื่องนี้ด้วย** เพื่อให้เป็นสองทาง: เครื่องนั้นสร้างกุญแจของตัวเอง (ถ้ายังไม่มี) แล้ว public key ของเขาจะถูกอนุญาตที่เครื่องนี้ (เครื่องนี้ต้องรับ SSH และบน Windows ต้องเปิดแบบผู้ดูแล)
- ไม่มีการคัดลอก private key ข้ามเครื่อง
- ครั้งแรกต้องล็อกอินได้ก่อน: เครื่องปลายทางต้องยังเปิดรหัสผ่านอยู่ ปุ่ม "เปิดรับ SSH" ปิดรหัสผ่าน จึงควร **จับคู่ก่อน แล้วค่อยเปิดรับ**
- macOS: ใช้เป็นเครื่องเชื่อมต่อ จับคู่ และสแกนหาเครื่องได้ การทำ Mac เป็นเซิร์ฟเวอร์ทำได้บางส่วน (ต้องเปิด Remote Login เองใน System Settings) ยังไม่ได้ทดสอบบน Mac จริง

## สแกนและควบคุมเครื่องใน LAN

กด **สแกน / ควบคุมเครื่องใน LAN** จะเปิดหน้าต่างแสดงทุกเครื่องที่ต่อเราเตอร์ตัวเดียวกัน ทั้งสายแลนและ Wi-Fi: ชื่อเครื่อง, IP, MAC, ระบบ, บริการที่เปิด (SSH, เว็บ, แชร์ไฟล์, Remote Desktop, VNC, เครื่องพิมพ์, กล้อง, NAS และพอร์ตเครื่องจักร เช่น Modbus) และจับคู่แล้วหรือยัง

- เว้นช่องช่วง IP = สแกนทุกวงที่เครื่องนี้ต่ออยู่ หรือพิมพ์ `192.0.2.0/24`, `192.0.2.1-254` ใช้เวลาราว 10 วินาที
- เครื่องที่เคยเจอแต่ปิดอยู่ยังแสดงเป็น "ออฟไลน์" เพื่อให้ปลุกด้วย Wake-on-LAN ได้
- เลือกเครื่องแล้วกด: **เปิด SSH** (หรือดับเบิลคลิกแถว), **จับคู่**, **Remote Desktop**, **เปิดเว็บ**, **เปิดไฟล์แชร์**, **ปลุกเครื่อง**, **คัดลอก IP**
- **รันคำสั่ง / รีสตาร์ท / ปิดเครื่อง** ทำผ่าน SSH ด้วยกุญแจ จึงต้องจับคู่ก่อน (Linux/macOS ต้องตั้ง sudo แบบไม่ถามรหัสสำหรับคำสั่งปิด/รีสตาร์ท)
- คอลัมน์ **หลักฐาน** บอกว่ารู้ข้อมูลแต่ละช่องมาจากไหน (ping, ARP, พอร์ต, NetBIOS, แบนเนอร์ SSH, หัวเว็บของอุปกรณ์) ช่องที่พิสูจน์ไม่ได้จะเว้นว่าง ไม่เดา (หลักการจาก REA) ส่วน MAC ที่ขึ้นว่า "สุ่ม" มักเป็นมือถือ
- **ตรวจว่าทำไมเข้าไม่ได้** ไล่ตรวจทีละชั้น: ping, พอร์ต 22, แบนเนอร์, กุญแจ, วิธีล็อกอินที่เครื่องนั้นรับ แล้วหยุดที่ชั้นแรกที่ติด พร้อมบอกวิธีแก้ของชั้นนั้น
- **ให้เครื่องนี้มองเห็นในวง LAN** (ต้องเป็นผู้ดูแล) ตั้งเครือข่ายเป็น Private เปิด Network Discovery แชร์ไฟล์ และ ping เฉพาะวง LAN ทำบนทุกเครื่องที่อยากให้มองเห็นกัน
- ถ้าไม่เห็นเครื่องที่ต่อ Wi-Fi: ปิด "AP isolation / client isolation" ในเราเตอร์ และอย่าต่อผ่าน Wi-Fi ของแขก (guest)

## แผนผังเครือข่าย

แผนผังขึ้นเป็นอย่างแรกในหน้าต่างหลัก (แท็บ **แผนผังเครือข่าย** ส่วนบันทึกว่าแต่ละปุ่มทำอะไรอยู่ในแท็บ **ผลลัพธ์** ซึ่งสลับให้เองเมื่อกดงาน) โปรแกรมวาดทุกเครื่องที่สแกน, audit ล่าสุด และ Tailscale เจอจริง ไม่มีเครื่องสมมติ: เจอ 4 เครื่องก็แสดง 4 เจอ 0 ก็ขึ้น "ยังไม่พบเครื่อง กดสแกน"

- **สองมุมมอง**: ไม่เกิน 12 เครื่อง = เราเตอร์อยู่กลาง อินเทอร์เน็ตบนซ้าย เครื่อง Tailscale ที่อยู่นอกวงนี้บนขวา และสายลงไปหาแต่ละเครื่องเรียงตาม IP · เกิน 12 = ไทล์จัดกลุ่มตามวง IP / คำนำหน้าชื่อ / ชนิด สลับเองได้ ข้อมูลเดิมได้ภาพเดิมเสมอ
- **ไอคอนตามหลักฐาน**: เราเตอร์ = default gateway, เดสก์ท็อป/โน้ตบุ๊ก/เซิร์ฟเวอร์ = ชนิดตัวเครื่องที่เครื่องรายงานเอง (เครื่องนี้อ่านเอง เครื่องที่จับคู่แล้วอ่านตอน audit), เครื่องพิมพ์ = พอร์ต 631/9100/515, กล้อง = 554, ทีวี = 8008/8009/7000, NAS = 5000/5001 คู่กับ 445, PLC = 502/102/44818, HMI = ชื่อขึ้นต้น HMI, มือถือ = Tailscale บอกว่า android/iOS หรือ MAC สุ่มและไม่มีพอร์ตเปิด นอกนั้นเป็น "ไม่ทราบชนิด" แก้ชนิดเองได้ในแผงข้าง (เก็บใน `devices.json`)
- **เส้น**: ทึบ = สายแลน, ประ = Wi-Fi, จุดจาง = ไม่ทราบ (รู้เฉพาะเครื่องที่ audit แล้ว), เขียวมีจุดวิ่ง = จับคู่ SSH แล้ว · ป้าย **TS** มุมกล่อง = เครื่องมี Tailscale (ไม่ได้แปลว่าเข้าทุกบริการได้ ดูพอร์ตในแผงข้าง) · กลุ่มมุมขวา = เครื่อง Tailscale ที่อยู่นอกวงนี้ · จุดสีมุมเครื่อง = ผล audit
- **ชี้** ที่เครื่องเพื่อดูการ์ดย่อ **คลิก** เพื่อดูทั้งหมด (ชื่อและที่มา, ชนิดและหลักฐาน, IP/MAC, พอร์ตพร้อมสี audit, การจับคู่ SSH) พร้อมปุ่ม เปิด SSH, จับคู่, ตรวจว่าทำไมเข้าไม่ได้, ตรวจความปลอดภัย, เปลี่ยนชนิด และส่วน **ควบคุม** (ปิด/เปิดพอร์ต, ไฟร์วอลล์, ห้ามแอปแก้, เปิดจากนอกบ้านแบบมีเวลา)
- **ป้ายเหลืองบนกล่อง** = มีการเปิดพอร์ตจาก Tailscale แบบมีเวลาที่ยังไม่หมด · กดปิดได้ในแผงข้าง
- **การเคลื่อนไหว**: เส้นวาดออกแล้วเครื่องลอยขึ้น = เจอเครื่อง, ไทล์เลื่อน = เปลี่ยนการจัดกลุ่ม, จุดวิ่ง = ส่งข้อมูลได้จริง, จุดเต้นช้า = ออนไลน์, กะพริบแดงช้า = พอร์ตเสี่ยง · เครื่องเดิมไม่เล่นซ้ำตอนรีเฟรช (ทุก 30 วินาทีขณะหน้าต่างอยู่ด้านหน้า) · ปิด "แสดงภาพเคลื่อนไหว" ใน Windows แล้วแผนผังจะนิ่ง

## ตรวจความปลอดภัย

ในหน้าต่างสแกน กด **ตรวจความปลอดภัย** (หรือ `-Action audit`) โปรแกรมจะดูทุกเครื่องที่สแกนเจอ ว่าเปิดพอร์ตอะไร ใครเข้าได้ และปลอดภัยไหม แถวผลมีหลักฐานและวิธีแก้เสมอ

**สีแปลว่าอะไร**

- **แดง** แก้ทันที: Telnet/FTP, SMBv1, SSH ที่ยังรับรหัสผ่าน, Remote Desktop ไม่บังคับ NLA, ไฟร์วอลล์ปิด, กฎเปิดให้ทุกที่บนเครือข่าย Public, พอร์ตที่เข้าจากอินเทอร์เน็ตได้, พอร์ตเครื่องจักร (Modbus, S7 ฯลฯ) ที่เข้าได้จากวงอื่นหรือ Tailscale
- **เหลือง** ตรวจว่าตั้งใจเปิด: Remote Desktop / VNC / แชร์ไฟล์ที่เปิดให้ทั้งวง, โปรแกรมที่รับการเชื่อมต่อแต่ไม่ใช่บริการที่รู้จัก, หน้าเว็บตั้งค่าอุปกรณ์ (มักยังใช้รหัสผ่านเริ่มต้น), UPnP ที่เราเตอร์, พอร์ตที่เปิดกว้างตอนไฟร์วอลล์ยังปิด
- **เขียว** ปลอดภัย: ฟังเฉพาะในเครื่อง, ไฟร์วอลล์บล็อก, หรือเปิดเฉพาะวง LAN / เฉพาะ Tailscale และใช้กุญแจ
- **เทา** ตรวจไม่ได้ / ไม่ทราบ: เครื่องปิด, SSH เข้าไม่ได้, หรืออุปกรณ์ที่รู้แค่ว่าพอร์ตเปิด จะบอกเหตุผลเสมอ ไม่เดา

**ปุ่มสั่ง (เปลี่ยนเครื่องจริง ทุกครั้งถามก่อน และย้อนได้)**

คอลัมน์ **สั่ง** ในหน้าต่างตรวจ และปุ่มใต้พอร์ตในแผงข้างของแผนผัง ใช้ชุดเดียวกัน

- **ปิดพอร์ตนี้** · ปิดกฎที่เปิดพอร์ตนั้น (Windows ไม่ลบกฎ · Linux ใส่ deny) · กด **เปิดคืน** เพื่อย้อน
- **ปิดทุกพอร์ตที่เสี่ยง (n)** · นับเฉพาะแถวแดงที่ปุ่มกดได้ · ถามครั้งเดียวแล้วทำทีละรายการ
- **เปิดไฟร์วอลล์** · คงพอร์ตที่ใช้อยู่ให้เปิดเฉพาะวง LAN และ Tailscale ก่อน แล้วค่อยเปิดไฟร์วอลล์ · รายการพอร์ตที่จะคงไว้โชว์ในกล่องยืนยัน
- **ลบการเปิดพอร์ตที่เราเตอร์** · ลบ UPnP mapping · ย้อนได้ด้วยการใส่ mapping เดิมคืน
- **ตั้งเป็นห้ามแก้ / เลิกห้ามแก้** · เครื่องในรายการนี้แอปจะไม่กดปิดหรือเปิดพอร์ตให้
- **เปิดจากนอกบ้าน** · เปิด SSH / Remote Desktop / พอร์ตที่เลือก เป็นเวลา 1–8 ชม. ให้เฉพาะวง Tailscale (`100.64.0.0/10`) · หมดเวลาปิดเอง · กด **ปิดตอนนี้** ได้ก่อนหมดเวลา
- **ไม่ปิด SSH (พอร์ต 22)** และไม่แตะเครื่องที่ตั้งห้ามแก้ · พอร์ต Docker บน Linux กดไม่ได้ (ต้องแก้ใน compose)
- เครื่อง Linux ที่ต้องใส่รหัส sudo · แอปเปิดหน้าต่าง `ssh` ให้พิมพ์เอง แอปไม่เก็บรหัส

ทุกแถวมี **หลักฐาน** (กฎไฟร์วอลล์ที่เปิดให้, ที่อยู่ที่ฟัง, ชื่อโปรแกรม, สิ่งที่สแกนเห็น) และ **วิธีแก้** หนึ่งประโยค ชี้เมาส์ที่แถวเพื่ออ่านเต็ม

- เครื่องนี้: อ่านพอร์ต โปรแกรม และกฎไฟร์วอลล์ได้โดยไม่ต้องเป็นผู้ดูแล
- เครื่องที่จับคู่แล้ว (Windows และ Linux): อ่านผ่าน SSH ด้วยกุญแจ พร้อมกันทีละ 8 เครื่อง เครื่องละไม่เกิน 20 วินาที เครื่องที่ปิดอยู่จะเป็นสีเทาพร้อมสาเหตุ ไม่ทำให้ทั้งรอบค้าง
- อุปกรณ์อื่น (ทีวี กล้อง เครื่องพิมพ์): รู้เฉพาะพอร์ตที่สแกนเห็นจากข้างนอก
- **อินเทอร์เน็ต**: ถามเราเตอร์ผ่าน UPnP (ไม่ตอบภายใน 5 วินาที = ไม่ทราบ) ถ้า IP ฝั่ง WAN เป็น IP ภายใน แปลว่าอยู่หลัง CGNAT ของผู้ให้บริการ การ forward พอร์ตจะเข้าจากนอกบ้านไม่ได้ IP ที่โลกเห็นอ่านจาก Tailscale ไม่ถามเว็บภายนอก
- **ทดสอบจากข้างนอก (exit node)**: ถ้ามีมือถือ Android ใน Tailscale ที่เปิด "Run as exit node" และใช้เน็ตมือถืออยู่ ปุ่มนี้จะให้เน็ตของเครื่องนี้ออกทางมือถือชั่วคราว (ราว 1 นาที) แล้วเคาะ IP บ้านจากข้างนอกทีละพอร์ต เสร็จแล้วตั้งค่าคืนเสมอแม้เกิดข้อผิดพลาด
- ผลแต่ละรอบบันทึกเป็น `audit-ปีเดือนวัน-เวลา.json` ข้างไฟล์ `config.json` แถวที่ไม่มีในรอบก่อนจะมีป้าย **ใหม่**
- **วงที่ห้ามเคาะพอร์ต** (เช่นสายการผลิต): ใส่ในไฟล์ `ranges.json` ข้าง `config.json` เช่น `[{ "cidr": "10.10.0.0/24", "safe": true, "label": "สายการผลิต" }]` วงนั้นจะได้แค่ ARP และ ping ไม่เกิน 20 ครั้งต่อวินาที ไม่มีการเชื่อมต่อ TCP เลย

## เชิญเครื่องเข้าวง

แตะเครื่องใหม่แค่ครั้งเดียว ที่เครื่องนี้เปิดโปรแกรมแบบผู้ดูแล แล้วเปิดหน้าต่างสแกน

**เชิญเครื่อง** (เครื่องใหม่อยู่วง LAN หรือ Tailscale เดียวกัน)
1. กด **เชิญเครื่อง** จะได้ลิงก์ คำสั่งสำหรับ Linux/macOS และ **รหัสยืนยัน 6 ตัว** ลิงก์ใช้ได้ 15 นาที
2. ที่เครื่อง Windows ใหม่ เปิดลิงก์ ดาวน์โหลด `join.cmd` แล้วดับเบิลคลิก กดยืนยันสิทธิ์ผู้ดูแล (Linux/macOS: วางคำสั่ง `curl … | sh`)
3. เทียบรหัสยืนยันบนเครื่องใหม่กับหน้าจอนี้ ต้องตรงกัน ถ้าไม่ตรงอย่าติดตั้งต่อ (รหัสนี้จับได้ถ้ากุญแจถูกสลับ แต่กันเครื่องในวงที่ดักแก้ไฟล์ดาวน์โหลดทั้งชุดไม่ได้ เพราะลิงก์เป็น HTTP ธรรมดา เครื่องสำคัญให้ใช้ชุด USB)
4. เครื่องใหม่ติดตั้ง OpenSSH Server กับ SSH LAN เปิดพอร์ต 22 เฉพาะ LAN/Tailscale เชื่อกุญแจของเครื่องนี้ แล้วส่ง public key ของตัวเองกลับมา
5. เครื่องนี้ถามให้คุณอนุญาตเครื่องนั้นก่อน โดยแสดงชื่อ IP และรหัสกุญแจของเครื่องนั้น (เครื่องนั้นแสดงรหัสเดียวกัน) แล้วทดสอบว่ากุญแจเข้าได้จริง เพิ่ม `ssh <ชื่อ>` และอนุญาตให้เครื่องนั้นเข้ามา รหัสผ่านยังใช้ได้เหมือนเดิม ถ้าติ๊ก **ใช้กุญแจอย่างเดียว** จะปิดรหัสผ่านบนเครื่องนั้นหลังทดสอบกุญแจผ่าน

- ติ๊ก **ลง Tailscale ด้วย** เพื่อลง Tailscale ให้เครื่องใหม่
- แพ็กเกจถูกตรวจ SHA-256 ก่อนติดตั้ง ทุกขั้นบนเครื่องใหม่บันทึกใน `join.log`
- หมด 15 นาที กด **หยุดเชิญ** หรือปิดโปรแกรม: เว็บเชิญและกฎไฟร์วอลล์ `sshlan-invite` ถูกปิด

**สร้างชุดติดตั้ง USB** (เครื่องที่ยังไม่อยู่วงเดียวกัน) เลือกโฟลเดอร์หรือแฟลชไดรฟ์ ที่เครื่องใหม่ดับเบิลคลิก `join.cmd` จากนั้นที่เครื่องนี้ สแกน เลือกเครื่องนั้น แล้วกด **จับคู่** ไม่ต้องใส่รหัสผ่าน

คำสั่ง: `ssh-lan.ps1 -Action invite` (เพิ่ม `-Usb E:\` เพื่อสร้างชุด USB)

## IP ของเซิร์ฟเวอร์เปลี่ยน

บนเครื่องเชื่อมต่อ กดปุ่มหลักอีกครั้ง สคริปต์จะหาเซิร์ฟเวอร์เอง: ลอง IP ที่เคยบันทึกไว้ก่อน ถ้าไม่เจอจะสแกนวง LAN ของเครื่องนี้หาเครื่องที่เปิดพอร์ต 22 และเลือกเครื่องที่กุญแจของคุณเข้าได้ แล้วอัปเดต `~/.ssh/config` ให้ รองรับทุกช่วง IP ในบ้าน (`10.x`, `172.16-31.x`, `192.168.x`)

## Linux

```bash
chmod +x scripts/ssh-lan/ssh-lan.sh && scripts/ssh-lan/ssh-lan.sh
```

## ตั้งค่า

ไฟล์ `%LocalAppData%\Ssh-Lan-Prime-Studio\config.json` (ไม่มีค่าของเครื่องใครฝังในโค้ด):

- `hostAlias` ชื่อที่ใช้ใน `~/.ssh/config` (ค่าเริ่มต้น `ssh-lan`)
- `identityFile` ชื่อไฟล์กุญแจใน `~/.ssh` (ค่าเริ่มต้น `id_ed25519_lan`)
- `serverUser` ชื่อผู้ใช้ที่ล็อกอินเข้าเซิร์ฟเวอร์ (ค่าเริ่มต้น ชื่อผู้ใช้ปัจจุบัน)
- `serverHost`, `serverIpSearch` ชื่อ/IP ของเซิร์ฟเวอร์ที่อยากให้ลองก่อน (ไม่ต้องใส่ก็ได้)
